🔌 Módulo 2.1: Desenvolvimento com APIs de IA

Integre OpenAI, Anthropic e outras APIs em suas aplicações com SDKs Python e JavaScript

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: APIs REST que permitem integrar modelos GPT-4, GPT-4o, Claude Sonnet/Opus em suas aplicações. Fazem requisições HTTP com prompts e recebem respostas estruturadas em JSON. Acesso programático aos LLMs mais poderosos do mercado.

    Por que aprender: Construir aplicações customizadas sem depender de interfaces web. Automação completa, integração com sistemas existentes, controle total sobre prompts e parâmetros. Essencial para desenvolvedores profissionais de IA.

    Conceitos chave: REST APIs, authentication tokens, request/response structure, model selection, streaming responses, error handling

  • O que é: Bibliotecas oficiais como openai-python, anthropic-sdk-python, OpenAI Node.js que abstraem chamadas HTTP complexas. Métodos simples como client.chat.completions.create() encapsulam toda a complexidade de autenticação, retry logic e parsing.

    Por que aprender: Acelera desenvolvimento em 10x comparado a fazer requisições HTTP manuais. SDKs incluem type safety, auto-complete, melhores práticas built-in e atualizações automáticas quando APIs mudam. Menos bugs, código mais limpo.

    Conceitos chave: SDK installation, client initialization, async/await patterns, type hints, streaming handlers, batch processing

  • O que é: Tokens são unidades de cobrança (~4 chars = 1 token). Rate limits controlam quantas requisições/tokens por minuto. Otimização envolve reduzir tokens no prompt, cachear respostas, usar modelos menores quando possível, implementar queues para respeitar limites.

    Por que aprender: Custos de API podem explodir sem otimização. Aplicação mal otimizada gasta 5-10x mais que o necessário. Rate limits mal gerenciados causam falhas em produção. Otimização = economia + performance + reliability.

    Conceitos chave: Token counting, prompt compression, response caching, rate limit handling, exponential backoff, queueing strategies

  • O que é: Proteger API keys usando variáveis de ambiente (.env), nunca commitando em Git. Validar inputs do usuário para prevenir prompt injection. Implementar timeout e error handling robusto. Logging sem expor dados sensíveis. Compliance com LGPD/GDPR.

    Por que aprender: API keys vazadas custam milhares de dólares em minutos. Prompt injection pode fazer IA executar comandos maliciosos. Aplicações sem error handling quebram em produção. Segurança não é opcional - é requisito para produção.

    Conceitos chave: Environment variables, input sanitization, prompt injection prevention, error handling, secure logging, API key rotation

🏗️ Módulo 2.2: Arquitetura de Aplicações com IA

Projete sistemas escaláveis com design patterns, pipelines e gerenciamento de estado

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Padrões arquiteturais específicos para IA: Strategy Pattern (trocar modelos dinamicamente), Chain of Responsibility (pipeline de prompts), Observer (monitorar performance), Factory (criar instâncias de diferentes LLMs), Adapter (unificar interfaces de APIs diferentes).

    Por que aprender: Evita refatoração massiva quando precisar trocar de modelo ou provider. Código modular facilita testes e manutenção. Patterns testados em batalha previnem armadilhas comuns. Aplicações profissionais exigem arquitetura sólida.

    Conceitos chave: Strategy pattern, chain of responsibility, factory pattern, dependency injection, interface abstraction, modularity

  • O que é: Sequências de transformações: input → preprocessamento → enriquecimento → chamada LLM → pós-processamento → validação → output. Cada etapa é independente, testável e pode falhar gracefully. Pipelines podem ser paralelos ou sequenciais.

    Por que aprender: Tarefas complexas quebradas em steps simples são mais fáceis de debugar e otimizar. Reutilização de componentes entre projetos. Facilita A/B testing de diferentes abordagens. Essencial para produção de qualidade enterprise.

    Conceitos chave: Pipeline architecture, data transformation, parallel processing, error propagation, composability, async workflows

  • O que é: Como manter contexto entre interações: memória de curto prazo (últimas N mensagens), longo prazo (vector DB com histórico relevante), state machines para conversas complexas. Persistência em Redis/PostgreSQL. Session management.

    Por que aprender: Conversas sem memória são frustrantes (IA esquece tudo a cada mensagem). Gerenciamento eficiente de estado economiza tokens mantendo contexto relevante. Chatbots profissionais precisam lembrar preferências e histórico do usuário.

    Conceitos chave: Session state, conversation memory, context windows, state persistence, memory optimization, conversation summarization

  • O que é: Estratégias de cache: respostas completas (Redis), embeddings computados, resultados intermediários. Lazy loading, prefetching para reduzir latência. Load balancing entre modelos. Monitoring de métricas (latência, throughput, error rate).

    Por que aprender: APIs de LLM são lentas (2-10s). Cache reduz custos em 60-80% e latência em 95%. Performance ruim = usuários abandonam app. Aplicações que escalam precisam de caching inteligente e otimização agressiva.

    Conceitos chave: Response caching, Redis integration, cache invalidation, CDN strategies, performance monitoring, latency optimization

📚 Módulo 2.3: RAG e Knowledge Bases

Implemente Retrieval Augmented Generation com vector databases e estratégias avançadas

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Bancos especializados em armazenar e buscar vetores (embeddings). Pinecone (managed cloud), Weaviate (open-source, rich filtering), Chroma (lightweight, ideal para protótipos). Suportam busca por similaridade em milhões de vetores em milissegundos.

    Por que aprender: RAG impossível sem vector DB eficiente. PostgreSQL com pgvector serve para protótipos, mas produção precisa de DB especializado. Escolha errada = custos altos + performance ruim. Conhecer trade-offs economiza meses de refatoração.

    Conceitos chave: Vector indexing, similarity search, HNSW algorithm, metadata filtering, hybrid search, performance tuning

  • O que é: Dividir documentos em chunks otimizados: tamanho fixo (512 tokens), semântico (por parágrafos/seções), overlap (20% entre chunks). Metadata tagging para filtering. Retrieval com top-k similarity + threshold filtering.

    Por que aprender: Chunking ruim = retrieval irrelevante = respostas incorretas. Chunk muito pequeno perde contexto, muito grande dilui sinal. 80% da qualidade do RAG vem de bom chunking. É arte + ciência que requer experimentação.

    Conceitos chave: Semantic chunking, overlap strategies, metadata enrichment, top-k retrieval, relevance scoring, context optimization

  • O que é: Combinar busca vetorial (semântica) com BM25 (keyword). Reranking usa modelos como Cohere Rerank ou cross-encoders para reordenar top-k results. Fusion de scores usando RRF (Reciprocal Rank Fusion). Melhora recall e precision.

    Por que aprender: Busca puramente vetorial falha em queries específicas (nomes, códigos). Hybrid search captura melhor de ambos mundos. Reranking melhora relevância em 30-50%. Técnica usada por sistemas RAG de ponta como Perplexity.

    Conceitos chave: Hybrid search, BM25 algorithm, reciprocal rank fusion, reranking models, precision/recall optimization, query expansion

  • O que é: Métricas para medir qualidade: retrieval (precision@k, recall@k, MRR), generation (faithfulness, answer relevancy, context relevancy). Frameworks como RAGAS automatizam avaliação. Criar golden dataset de Q&A para benchmarking.

    Por que aprender: "O que não é medido não pode ser melhorado". Sem métricas, otimização é adivinhação. Avaliação sistemática permite comparar estratégias objetivamente. Essencial para iterar e melhorar sistemas RAG continuamente.

    Conceitos chave: RAGAS framework, precision/recall metrics, faithfulness evaluation, answer relevancy, A/B testing, benchmark datasets

🎓 Módulo 2.4: Fine-tuning e Customização

Aprenda a treinar modelos customizados, preparar datasets e avaliar resultados

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Processo de adaptar modelos pré-treinados (GPT-3.5, Llama) com seus dados específicos. Fine-tuning completo vs LoRA (Low-Rank Adaptation) para eficiência. OpenAI Fine-tuning API, Hugging Face Transformers. Ajusta pesos do modelo para seu domínio.

    Por que aprender: Quando prompts atingem limite, fine-tuning leva performance ao próximo nível. Melhora consistência de formato, reduz tokens necessários, permite comportamentos impossíveis via prompting. Diferencial para aplicações enterprise sérias.

    Conceitos chave: Transfer learning, LoRA adapters, hyperparameter tuning, training loops, gradient descent, model checkpointing

  • O que é: Coletar/criar dataset de qualidade: exemplos input-output representativos (mínimo 50-100 para OpenAI, 1000+ para melhor performance). Formato JSONL. Cleaning, deduplication, balanceamento de classes. Train/validation/test splits.

    Por que aprender: "Garbage in, garbage out" - modelo só aprende o que está nos dados. Dataset ruim resulta em modelo pior que baseline. 80% do sucesso de fine-tuning vem de dados bem preparados. É o trabalho mais importante e subestimado.

    Conceitos chave: Data collection, JSONL format, data cleaning, class balancing, train/val/test splits, data augmentation

  • O que é: Comparar modelo fine-tuned vs baseline em validation set. Métricas: accuracy, F1, perplexity para tarefas específicas. A/B testing em produção: 10% tráfego para novo modelo, 90% baseline. Monitorar degradação, edge cases. Rollback se performance cair.

    Por que aprender: Fine-tuning sem avaliação rigorosa é perigoso - pode piorar performance. A/B testing cientificamente válido evita deploy de modelos ruins. Processo disciplinado de avaliação é marca de engenharia profissional de ML.

    Conceitos chave: Validation metrics, A/B testing, statistical significance, baseline comparison, model monitoring, rollback strategies

🤖 Módulo 2.5: Agentes e Workflows Complexos

Construa agentes autônomos com LangChain, LlamaIndex e frameworks avançados

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: LangChain: framework completo para chains, agents, tools. LlamaIndex: especializado em indexação e retrieval. Abstraem complexidade de criar agentes que usam ferramentas, mantêm memória, fazem reasoning. Ecosystem rico de integrações.

    Por que aprender: Construir agentes do zero é complexo demais. Frameworks economizam meses de desenvolvimento e incluem best practices. Comunidade ativa, documentação rica, updates frequentes. Indispensável para desenvolvimento ágil de aplicações LLM.

    Conceitos chave: LangChain chains, agents, tools, memory, callbacks, LlamaIndex indices, query engines, retrievers

  • O que é: ReAct (Reasoning + Acting): agente pensa em voz alta, decide que ferramenta usar, executa, observa resultado, repete. Planning: decomposição de tarefas complexas em subtarefas. Tool use: integração com APIs, calculadoras, browsers, code interpreters.

    Por que aprender: Agentes ReAct são 3-5x mais eficazes que prompts simples em tarefas complexas. Tool use expande capacidades da IA infinitamente. Planning permite resolver problemas multi-step que seriam impossíveis em single-shot. Fronteira da IA aplicada.

    Conceitos chave: ReAct prompting, task decomposition, tool selection, function calling, observation-action loops, planning strategies

  • O que é: Múltiplos agentes especializados colaborando: pesquisador busca informações, analista processa dados, escritor cria relatório, revisor valida. Coordenação via supervisor ou comunicação peer-to-peer. Frameworks como AutoGen, CrewAI.

    Por que aprender: Tarefas complexas precisam de especialização - um agente generalista não basta. Multi-agent systems imitam times humanos. Cada agente otimizado para papel específico = qualidade superior. Futuro de automação de conhecimento.

    Conceitos chave: Agent specialization, coordination patterns, supervisor agents, communication protocols, AutoGen framework, role assignment

  • O que é: Gerenciar execução de agentes: retry logic quando ferramentas falham, fallbacks quando agente fica preso em loop, timeouts para prevenir execuções infinitas, logging para debug. State machines para workflows determinísticos. Circuit breakers para serviços externos.

    Por que aprender: Agentes em produção falham de formas criativas. Sem error handling robusto, falhas cascateiam e aplicação quebra. Orquestração profissional = confiabilidade. Diferença entre protótipo interessante e sistema production-ready.

    Conceitos chave: Retry strategies, fallback mechanisms, timeout handling, circuit breakers, logging/debugging, state management

👁️ Módulo 2.6: Computer Vision Avançada

Detecção de objetos, segmentação e aplicações industriais de visão computacional

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Object detection (YOLO, Faster R-CNN): identificar e localizar objetos com bounding boxes. Segmentation (Segment Anything Model): separar imagem em regiões pixel-perfect. Instance segmentation vs semantic segmentation. Real-time processing.

    Por que aprender: Base para automação visual: carros autônomos, sistemas de segurança, controle de qualidade industrial, contagem automática, análise de vídeo. Mercado crescendo 20%/ano. Habilidade técnica altamente valorizada.

    Conceitos chave: YOLO architecture, bounding boxes, confidence scores, non-max suppression, SAM model, instance segmentation

  • O que é: Reconhecimento facial: identificar pessoas comparando embeddings faciais. Tracking: manter ID consistente em vídeo. Landmark detection (olhos, nariz, boca). Liveness detection para prevenir spoofing. APIs como DeepFace, face-recognition.

    Por que aprender: Aplicações em segurança, autenticação biométrica, análise de emoções, filtros AR, attendance tracking. Importante entender limitações éticas e vieses. Regulação crescente (LGPD, GDPR) exige conhecimento profundo.

    Conceitos chave: Face embeddings, landmark detection, face matching, tracking algorithms, liveness detection, bias mitigation

  • O que é: Inspeção de qualidade em manufatura (detectar defeitos), OCR avançado para documentos, análise de imagens médicas, agricultura de precisão (drones para monitorar plantações), varejo (prateleiras inteligentes, checkout sem caixa).

    Por que aprender: Indústria 4.0 depende de visão computacional. ROI comprovado: redução de defeitos em 60-90%, economia de custos massiva. Oportunidades em consultorias, implementação de sistemas, desenvolvimento de produtos especializados.

    Conceitos chave: Defect detection, OCR/document AI, medical imaging, anomaly detection, edge deployment, real-time processing

📝 Módulo 2.7: NLP e Text Processing

Named Entity Recognition, análise de sentimento e processamento avançado de texto

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Extrair entidades nomeadas de texto: pessoas, organizações, locais, datas, valores monetários. Modelos como spaCy, Transformers (BERT-based NER). Custom NER para domínios específicos (entidades médicas, jurídicas). Entity linking para disambiguação.

    Por que aprender: Fundamental para extração de informações estruturadas de texto não-estruturado. Alimenta knowledge graphs, sistemas de busca, compliance, análise de contratos. Base para automação de processos que dependem de documentos.

    Conceitos chave: Entity extraction, spaCy pipelines, BERT-based NER, custom entity types, entity linking, relation extraction

  • O que é: Tradução neural (Google Translate, DeepL, GPT-4). Modelos multilíngues (mBERT, XLM-R) que funcionam em 100+ idiomas. Zero-shot cross-lingual transfer. Translation quality assessment. Adaptação cultural além de tradução literal.

    Por que aprender: Globalização exige suporte multilíngue. Modelos atuais atingem qualidade próxima a tradutores humanos em muitos pares de idiomas. Permite escalar produtos para mercados internacionais sem contratar tradutores para tudo. Vantagem competitiva global.

    Conceitos chave: Neural machine translation, multilingual embeddings, zero-shot transfer, translation quality metrics, cultural adaptation

  • O que é: Classificar texto por sentimento (positivo/negativo/neutro), emoção (alegria, raiva, medo), ou categorias customizadas. Aspect-based sentiment (o que especificamente é positivo/negativo). Fine-grained vs coarse sentiment. Modelos transformer-based.

    Por que aprender: Análise de feedback de clientes em escala, monitoramento de brand reputation, detecção de crises, triagem de tickets de suporte. Empresas tomam decisões de produto baseadas em sentiment analysis. ROI direto e mensurável.

    Conceitos chave: Sentiment classification, aspect-based sentiment, emotion detection, text classification, zero-shot classification

  • O que é: Extrair informações estruturadas de texto não-estruturado: formulários, contratos, faturas, emails. Combina NER, relation extraction, table extraction. LLMs com structured output (JSON mode). Validation e error correction.

    Por que aprender: Automação de data entry que consome horas humanas diariamente. Empresas gastam fortunas digitando informações de documentos. IE bem implementada economiza 90% desse esforço. Aplicação com ROI imediato e óbvio.

    Conceitos chave: Structured extraction, JSON mode, relation extraction, form parsing, validation strategies, error handling

🚀 Módulo 2.8: MLOps e Produção

Deploy, monitoring, CI/CD e otimização de custos para sistemas de IA em produção

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Deploy de modelos em produção: containerização (Docker), orquestração (Kubernetes), serverless (AWS Lambda, Cloud Functions), edge deployment. Model serving com FastAPI, TorchServe, TensorFlow Serving. Load balancing, auto-scaling.

    Por que aprender: Modelo que não está em produção não gera valor. Deploy robusto é diferença entre protótipo e produto. Conhecer opções (cloud, on-premise, edge) permite otimizar custo-performance. Habilidade crítica para ML engineers.

    Conceitos chave: Docker containers, Kubernetes, serverless, model serving, load balancing, auto-scaling, blue-green deployment

  • O que é: Monitorar performance de modelos: latência, throughput, error rates, model drift (performance degradando ao longo do tempo), data drift (distribuição de inputs mudando). Ferramentas: Prometheus, Grafana, Weights & Biases, Arize.

    Por que aprender: Modelos degradam silenciosamente em produção. Sem monitoring, você só descobre quando clientes reclamam. Observability permite detectar problemas proativamente, entender causa raiz, prevenir incidentes. Indispensável para SLA enterprise.

    Conceitos chave: Model monitoring, drift detection, observability, metrics tracking, alerting, Prometheus/Grafana

  • O que é: Continuous Integration/Deployment para ML: automatizar treino, testes, validação, deploy. GitHub Actions, GitLab CI, CircleCI. ML pipelines com DVC, MLflow. Automated retraining quando novos dados chegam. Version control para modelos e dados.

    Por que aprender: Processos manuais não escalam e são propensos a erros. CI/CD garante qualidade consistente, accelera iteração, permite múltiplos data scientists colaborarem sem conflitos. Padrão da indústria para times profissionais de ML.

    Conceitos chave: ML pipelines, automated testing, continuous training, model versioning, DVC, MLflow, GitHub Actions

  • O que é: Reduzir custos de infra ML: usar modelos menores quando possível, quantização (FP16, INT8), batch processing, spot instances, caching agressivo, escolher região cloud correta. Monitorar custos por feature/endpoint. Reserved capacity vs on-demand.

    Por que aprender: Custos de ML podem explodir rapidamente (GPUs caras, APIs com preço por token). Otimização pode reduzir custos em 60-80% sem sacrificar performance. Diferença entre projeto viável e inviável economicamente. CFOs amam ML engineers que entendem custos.

    Conceitos chave: Model quantization, batch processing, spot instances, cost monitoring, reserved capacity, infra optimization

⚖️ Módulo 2.9: Ética e Governança de IA

Bias, fairness, privacidade e compliance para desenvolvedores de IA responsável

📄 Abrir Página Completa 📥 Download PDF/MD

📚 Tópicos-chave do módulo:

  • O que é: Identificar e mitigar vieses em modelos: bias racial, gênero, idade. Técnicas de fairness: reweighting, adversarial debiasing, fairness constraints. Métricas: demographic parity, equalized odds. Tools como Fairlearn, AI Fairness 360.

    Por que aprender: Modelos enviesados causam danos reais (discriminação em crédito, contratação, justiça criminal). Além de ética, há risco legal e reputacional massivo. Empresas sérias exigem auditoria de fairness. Desenvolver IA responsável não é opcional.

    Conceitos chave: Algorithmic bias, fairness metrics, debiasing techniques, Fairlearn, demographic parity, equalized odds

  • O que é: Compliance com LGPD/GDPR: consentimento, minimização de dados, direito ao esquecimento, portabilidade. Técnicas de privacy-preserving ML: differential privacy, federated learning, synthetic data. Anonimização vs pseudonimização.

    Por que aprender: Multas de LGPD/GDPR chegam a 2% do faturamento global. Vazamentos de dados destroem reputação e causam processos. Conhecer requisitos legais previne problemas caros. Privacy-by-design é mandatório para empresas modernas.

    Conceitos chave: LGPD/GDPR compliance, differential privacy, federated learning, data anonymization, consent management

  • O que é: Documentação de sistemas de IA: model cards, datasheets, impact assessments. Auditabilidade: logs de decisões, explainability (SHAP, LIME), reproducibility. Governança: comitês de ética, approval workflows, risk classification. EU AI Act compliance.

    Por que aprender: Regulações de IA estão chegando (EU AI Act, propostas no Brasil). Setores regulados (saúde, finanças, governo) exigem auditoria completa. Documentação adequada protege empresa legalmente e facilita certificações. Requisito para vendas enterprise.

    Conceitos chave: Model cards, impact assessments, explainability, SHAP/LIME, audit trails, EU AI Act, governance frameworks
