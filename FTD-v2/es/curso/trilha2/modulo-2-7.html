🔤 El texto se convierte en datos

NLP (Procesamiento del lenguaje natural, procesamiento del lenguaje natural) es el conjunto de técnicas que permite a un programa leer, organizar y producir texto humano. El problema de partida siempre es el mismo: la computadora solo opera con números. Antes de clasificar una queja o resumir un contrato, el texto tiene que convertirse en una secuencia de números, y cada decisión que se toma en esa conversión afecta el resultado posterior.

Hasta alrededor de 2018, el trabajo de NLP estaba dominado por reglas y modelos pequeños entrenados para una sola tarea. Hoy, un LLM hace casi todo con una instrucción bien redactada. Pero los fundamentos siguen vigentes: los tokens cuestan dinero y caben en una ventana limitada, el texto sucio genera respuestas sucias y una misma palabra puede significar cosas distintas según el contexto.

📘 Términos nuevos

Tokenización es dividir el texto en partes (tokens) que están en el vocabulario del modelo. Los modelos actuales usan subpalabras, generadas por algoritmos como BPE (Codificación por pares de bytes): las palabras comunes se convierten en un token; las palabras poco frecuentes se dividen en partes. Normalización es estandarizar el texto antes de procesarlo: espacios, saltos de línea, mayúsculas y minúsculas, caracteres invisibles.

Qué es

Es el recorrido texto → tokens → ID numéricos → vectores. Los vectores (embeddings) contienen el significado que el modelo aprendió; todo lo que viene después —clasificar, extraer, buscar— opera sobre ellos.

✓ Normaliza siempre

  • ✓Unicode en forma NFC (los acentos compuestos y descompuestos se convierten en lo mismo).
  • ✓Espacios repetidos, tabulaciones y saltos de línea adicionales.
  • ✓Firmas de correo electrónico, pies de página y HTML que no aportan significado.
  • ✓Datos personales que no necesitan enviarse al modelo (LGPD, módulo 2.9).

✗ No destruyas la señal

  • ✗Quitar los acentos: «pais» y «país» dejan de ser diferentes.
  • ✗Eliminar «no» como palabra vacía: la frase invierte su sentido.
  • ✗Convertir todo a minúsculas cuando las siglas y los nombres son importantes.
  • ✗Borrar los emojis de las reseñas: suelen transmitir el sentimiento.

💡 Consejo

Con los LLM, la limpieza agresiva de las técnicas antiguas (lematización, eliminación de palabras vacías) perjudica más de lo que ayuda. Limpia el ruido de formato y los datos personales; deja el lenguaje tal como está.

Por qué aprender

Entender los tokens explica el costo que llega a fin de mes, por qué un documento «no cabe» en el contexto y por qué un texto mal depurado confunde al modelo. Es la base para dimensionar cualquier pipeline de texto antes de escribir la primera línea de código.

🏷️ Clasificar texto

Clasificación de texto es asignar a cada texto una etiqueta de una lista cerrada: el tema de una solicitud, el sentimiento de una reseña, la urgencia de un correo electrónico, si un mensaje es spam. Es la tarea de NLP más común en las empresas, porque permite dirigir, contar y priorizar sin que nadie tenga que leerlo todo.

Hay tres caminos. El clásico transforma el texto en conteos de palabras (TF-IDF) y entrena un modelo sencillo, como una regresión logística en scikit-learn: es rápido y barato, pero necesita cientos de ejemplos etiquetados. El ajuste fino de un modelo pequeño (de la familia BERT) ofrece alta calidad, con un costo de entrenamiento. Y el zero-shot con LLM clasifica solo con la lista de etiquetas y una instrucción, sin ningún entrenamiento.

📘 Términos nuevos

TF-IDF pondera cada palabra según su frecuencia en el texto y su rareza en el conjunto completo. Zero-shot es realizar la tarea sin ejemplos; few-shot es incluir algunos ejemplos en el propio prompt. Salida estructurada es obligar al modelo a responder en un formato legible por máquina, como JSON.

Qué es

Una función que recibe texto y devuelve una etiqueta de una lista definida por ti, preferiblemente con una justificación breve y en un formato que el resto del sistema pueda validar.

MétodoNecesitaConviene cuandoCuidado
TF-IDF + modelo linealCientos de ejemplos etiquetadosAlto volumen, etiquetas estables, costo mínimoNo entiende los sinónimos ni la ironía
Ajuste fino (BERT y similares)Ejemplos etiquetados y una GPUAlta calidad con baja latenciaVolver a entrenar con cada etiqueta nueva
LLM zero-shot/few-shotLista de etiquetas y una buena instrucciónEmpezar hoy, etiquetas que cambianCosto y latencia por elemento; validar la salida

Prueba: clasificador zero-shot local, guardado como classificador.py.

# Instalación: pip install openai   |   ollama pull qwen2.5:7b
# classificador.py — usa la ruta compatible con OpenAI de Ollama (local y gratis)
import json
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")  # Ollama ignora la clave
ROTULOS = ["entrega", "pagamento", "produto", "elogio", "outro"]

INSTRUCAO = (
    "Clasificas mensajes de clientes de una tienda en línea. "
    'Responde ÚNICAMENTE con JSON en el formato {"rotulo": "...", "motivo": "..."}. '
    "Etiquetas válidas: " + ", ".join(ROTULOS) + ". "
    "Usa 'outro' cuando ninguna corresponda. El motivo tiene un máximo de 12 palabras."
)

def classificar(texto: str) -> dict:
    resp = client.chat.completions.create(
        model="qwen2.5:7b",
        temperature=0,                              # la misma entrada, la misma salida (casi siempre)
        response_format={"type": "json_object"},    # obliga a devolver JSON válido
        messages=[{"role": "system", "content": INSTRUCAO},
                  {"role": "user", "content": texto}],
    )
    dado = json.loads(resp.choices[0].message.content)
    if dado.get("rotulo") not in ROTULOS:           # nunca confíes ciegamente en la salida
        dado["rotulo"] = "outro"
    return dado

if __name__ == "__main__":
    print(classificar("<pega aquí un mensaje real de un cliente, sin datos personales>"))

Cómo verificar: ejecuta python3 classificador.py. La salida debe ser un diccionario como {'rotulo': 'entrega', 'motivo': '...'}. Prueba cinco mensajes de etiquetas diferentes y uno que no tenga nada que ver con la tienda: debe quedar como "outro". Para usar una API de pago, cambia solo base_url, api_key e model.

💡 Consejo

Empieza con el LLM para descubrir las etiquetas adecuadas y reunir ejemplos. Cuando el volumen crezca y las etiquetas se estabilicen, usa las respuestas revisadas por personas para entrenar un clasificador pequeño y barato. Es una forma habitual de reducir costos sin perder calidad.

Por qué aprender

Casi todos los sistemas de atención, clasificación o análisis de opiniones empiezan con una clasificación. Saber elegir entre el método clásico, el ajuste fino y el LLM —y validar la salida— evita tanto un proyecto demasiado costoso como uno que falla con la primera respuesta fuera del formato.

🧾 Extraer entidades

NER (Reconocimiento de entidades nombradas, encontrar en el texto nombres de personas, empresas, lugares, fechas y valores, e indicar el tipo de cada uno. Así, un contrato se convierte en una fila de una hoja de cálculo: partes, valor, plazo, jurisdicción. Una noticia se convierte en una lista de las empresas mencionadas.

Hay dos familias de herramientas. Bibliotecas como spaCy incluyen modelos listos para portugués (pt_core_news_sm) que identifican personas, lugares y organizaciones con rapidez y costo cero. Para campos de tu negocio (número de pedido, nombre del producto, cláusula de penalización), un LLM con esquema JSON suele ser más flexible: describes los campos y el modelo los completa.

📘 Términos nuevos

JSON Schema es una descripción formal de los campos, los tipos y los requisitos de un JSON. Ollama acepta este esquema en el parámetro format y limita la generación para que la respuesta se ajuste a él. Etiquetas BIO (Begin, Inside, Outside) es la forma clásica de marcar entidades palabra por palabra durante el entrenamiento de modelos de NER.

Qué es

Extracción de información: localizar fragmentos con un significado específico dentro del texto libre y devolverlos organizados por tipo, listos para enviarlos a una base de datos o a otra etapa del pipeline.

Objetivo: extraer entidades con un esquema JSON y comprobar que no se haya inventado nada.

# Instalación: pip install requests   |   ollama pull qwen2.5:7b
import json, requests

CAMPOS = ["pessoas", "organizacoes", "locais", "datas", "valores"]
SCHEMA = {
    "type": "object",
    "properties": {c: {"type": "array", "items": {"type": "string"}} for c in CAMPOS},
    "required": CAMPOS,
}

def extrair(texto: str) -> dict:
    r = requests.post("http://localhost:11434/api/chat", json={
        "model": "qwen2.5:7b",
        "stream": False,
        "format": SCHEMA,                 # la respuesta se limita a este esquema
        "options": {"temperature": 0},
        "messages": [
            {"role": "system", "content": "Extrae las entidades del texto. Copia cada fragmento "
             "exactamente como aparece. No inventes: usa una lista vacía cuando no haya."},
            {"role": "user", "content": texto},
        ],
    }, timeout=120)
    r.raise_for_status()
    return json.loads(r.json()["message"]["content"])

texto = "<pega un párrafo de un contrato, una noticia o un correo electrónico>"
ents = extrair(texto)
print(json.dumps(ents, ensure_ascii=False, indent=2))

# Verificación contra invenciones: cada fragmento debe aparecer literalmente en el texto
for tipo, itens in ents.items():
    for item in itens:
        if item not in texto:
            print(f"ATENCIÓN [{tipo}] no aparece en el texto: {item!r}")

Cómo verificar: con la frase del diagrama, la salida debe tener las cinco listas completas y ninguna línea de "ATENCIÓN". Luego pega un texto sin fechas: fechas debe volver vacía. Si aparece una advertencia, el modelo reescribió o inventó un fragmento: trátalo como un error, no como un acierto.

💡 Consejo

Para entidades estándar en grandes volúmenes, prueba spaCy primero: pip install spacy e python -m spacy download pt_core_news_sm. Funciona en CPU, sin GPU, y sirve como punto de comparación para el LLM.

Por qué aprender

Buena parte del valor del NLP en las empresas está en extraer datos de documentos: notas, contratos, informes, currículums y correos electrónicos. Saber extraer con un esquema y verificar contra el texto original es lo que marca la diferencia entre una demostración y un proceso confiable.

📄 Resumir textos largos

Resumir parece sencillo hasta que el documento pasa de unas cuantas decenas de páginas. Incluso con ventanas de contexto grandes, los modelos tienden a prestar menos atención a la parte central de los textos muy largos, y un resumen único oculta de dónde viene cada afirmación. El método robusto es dividir, resumir las partes y luego unirlas, guardando la referencia de cada fragmento.

Hay dos tipos de resumen. El extractivo elige frases del original y las copia: es seguro porque nada se reescribe. El abstractivo reescribe con otras palabras: es más fluido, pero puede distorsionar el contenido. En textos jurídicos, médicos o financieros, funciona bien un punto medio: un resumen abstractivo con citas literales de los fragmentos que respaldan cada punto.

📘 Términos nuevos

Chunking consiste en dividir el documento en fragmentos (chunks) de tamaño controlado, de preferencia respetando las secciones y los párrafos. Superposición (overlap) consiste en repetir una parte del final de un fragmento al principio del siguiente para no cortar una idea por la mitad. Map-reduce consiste en aplicar la misma operación a cada fragmento (map) y luego combinar los resultados (reduce).

Qué es

Resumen por etapas: el documento se divide en fragmentos, cada fragmento recibe un resumen parcial con una referencia a su origen y, al final, un resumen final combina los parciales según el formato que necesita el lector.

Para quien toma decisiones

Cinco puntos, primero los riesgos, cada uno con la página de origen. Termina con "qué falta decidir".

Para quien ejecuta

Lista de obligaciones, plazos y responsables en una tabla. Nada de párrafos largos.

Para el sistema

JSON con campos fijos (tema, partes, fechas, valores) para indexar y filtrar después.

💡 Consejo

Divide según la estructura (títulos, cláusulas, secciones), no por una cantidad fija de caracteres. Un corte a mitad de una cláusula genera dos resúmenes parciales incorrectos.

Por qué aprender

Los informes, las actas, los expedientes y los manuales son extensos y se leen con prisa. Un resumen rastreable ahorra horas de lectura sin ocultar de dónde proviene cada conclusión; y el mismo método de dividir, procesar y reunir sirve para traducir, extraer y revisar documentos extensos.

🔎 Búsqueda semántica

La búsqueda por palabra clave solo encuentra lo que contiene la misma palabra. Quien pregunta «mi pedido no llegó» no encuentra el texto «plazo de entrega», aunque sea exactamente lo que busca. La búsqueda semántica compara significados: convierte la pregunta y los documentos en vectores y devuelve los documentos cuyos vectores están más cerca.

Esta es la pieza central de RAG (generación aumentada por recuperación), que vimos en el módulo sobre bases de conocimiento: antes de responder, el sistema busca los fragmentos relevantes y se los entrega al LLM. En producción, los vectores se almacenan en una base de datos propia, pgvector en Postgres, Qdrant o Chroma. Para aprender, basta con un array de NumPy.

📘 Términos nuevos

Similitud del coseno mide el ángulo entre dos vectores: cerca de 1, apuntan en la misma dirección (significados parecidos); cerca de 0, no tienen relación. Si los vectores están normalizados (longitud 1), el coseno se convierte en un simple producto escalar. Búsqueda híbrida combina palabras clave y vectores; es útil cuando importan los códigos y los nombres exactos.

Qué es

Búsqueda por proximidad de significado: un modelo de embeddings convierte los textos en vectores, y la consulta devuelve los textos más cercanos a la pregunta según el coseno, incluso si no comparten palabras.

Prueba: búsqueda semántica local con nomic-embed-text.

# Instala: pip install requests numpy   |   ollama pull nomic-embed-text
import requests
import numpy as np

def embed(textos: list[str]) -> np.ndarray:
    r = requests.post("http://localhost:11434/api/embed",
                      json={"model": "nomic-embed-text", "input": textos}, timeout=120)
    r.raise_for_status()
    v = np.array(r.json()["embeddings"], dtype=float)
    return v / np.linalg.norm(v, axis=1, keepdims=True)   # normaliza: coseno = producto escalar

# nomic-embed-text recomienda prefijos diferentes para documentos y consultas
docs = [
    "El plazo de entrega es de 5 a 10 días hábiles después de confirmar el pago.",
    "Las facturas vencidas se pueden volver a emitir en el área de clientes.",
    "Se aceptan cambios hasta 7 días corridos después de recibir el producto.",
    "<agrega aquí fragmentos de tu propia base, uno por elemento>",
]
D = embed(["search_document: " + d for d in docs])

def buscar(pregunta: str, k: int = 2) -> None:
    q = embed(["search_query: " + pregunta])[0]
    notas = D @ q
    for i in np.argsort(-notas)[:k]:
        print(f"{notas[i]:.3f}  {docs[i]}")

buscar("mi pedido todavía no llegó")

Cómo verificar: El primer resultado debería ser la frase sobre el plazo de entrega, aunque no incluya la palabra «pedido». Cambia la pregunta por «¿puedo devolver la camiseta?»; la frase sobre cambios debería quedar en primer lugar. Las puntuaciones varían según el modelo; compara el orden, no el valor absoluto.

Por qué aprender

La búsqueda semántica es la base de asistentes que responden con documentos de la empresa, de la deduplicación de solicitudes y de la recomendación de contenido. Entender el vector y la métrica permite diagnosticar por qué falla una búsqueda, antes de culpar al LLM por una respuesta deficiente.

🌍 Portugués y otros idiomas

La mayor parte de los datos de entrenamiento de los modelos todavía está en inglés. Los LLM actuales manejan bien el portugués, pero hay diferencias: más tokens para el mismo contenido, jerga y regionalismos mal interpretados, confusión entre el portugués de Brasil y el de Portugal, y errores con formatos locales: CPF, CEP, fechas en formato día/mes, coma decimal, «R$ 1.234,56».

Para traducir, tienes modelos abiertos especializados, como NLLB de Meta, y los LLM generales, que traducen bien y además siguen instrucciones de tono y glosario. Para los sistemas que reciben textos en varios idiomas, el estándar es detectar primero el idioma y decidir: procesar en el idioma original con un modelo multilingüe o traducir antes.

📘 Términos nuevos

Modelo multilingüe se entrena simultáneamente en varios idiomas y ubica frases equivalentes cerca unas de otras en el espacio de embeddings; por eso, una pregunta en portugués puede encontrar un documento en español. Glosario, en traducción, es la lista de términos que deben traducirse siempre de la misma manera (o que no deben traducirse, como los nombres de productos).

Qué es

Es tratar el idioma y los formatos locales como parte del problema: detectar el idioma, elegir el modelo y el prompt adecuados, estandarizar números, fechas y documentos brasileños, y probar con textos reales de tu público.

✓ Funciona bien

  • ✓Pedir explícitamente «portugués de Brasil» en el prompt del sistema.
  • ✓Convertir «R$ 1.234,56» y «03/02/2026» con código, no con el modelo.
  • ✓Validar CPF y CNPJ mediante el dígito de verificación después de la extracción.
  • ✓Glosario fijo en el prompt de traducción para los términos de la empresa.

✗ Errores comunes

  • ✗Probar solo con textos en inglés y publicar para clientes brasileños.
  • ✗Dejar que el modelo interprete «02/03» sin conocer el formato de fecha.
  • ✗Ignorar textos con errores tipográficos y abreviaturas de WhatsApp.
  • ✗Traducir y luego extraer, perdiendo los nombres y valores originales.

💡 Consejo

Arma tu conjunto de pruebas con mensajes como los escribe realmente tu cliente: con «vc», «pq», errores y audios transcritos. A los modelos que funcionan bien con texto limpio les puede ir mucho peor con texto informal, y solo la prueba te muestra cuánto.

Por qué aprender

Los ejemplos, tutoriales y benchmarks suelen estar en inglés. Quienes crean soluciones para el público brasileño deben conocer los errores típicos en portugués y los formatos locales; ahí es donde un sistema que "funcionó en la prueba" falla con el primer cliente real.

🧪 Pipeline y evaluación

Un pipeline de texto encadena las etapas de este módulo: normalizar, detectar el idioma, clasificar, extraer, validar y guardar. Cada etapa tiene una entrada y una salida definidas, y cada una puede fallar. Sin medir, no sabes qué etapa falló ni si un cambio de modelo o de prompt mejoró o empeoró el resultado.

La herramienta para esto es el conjunto de pruebas: unas decenas de ejemplos reales y anonimizados, con la respuesta correcta anotada por una persona. Cada cambio se prueba con ellos. El número que se obtiene no tiene que ser perfecto; tiene que poder compararse entre versiones.

📘 Términos nuevos

Exactitud es la proporción de aciertos sobre el total. Precisión de una etiqueta: de los elementos que el modelo marcó con ella, cuántos eran correctos. Exhaustividad (recall): de los elementos que realmente correspondían a esa etiqueta, cuántos encontró el modelo. F1 combina ambas. En clases desequilibradas, revisa la precisión y la exhaustividad por etiqueta, no solo la exactitud.

Qué es

Una secuencia de etapas de texto con un contrato de entrada y salida, acompañada de un conjunto de pruebas etiquetado que mide cada cambio antes de que llegue a los usuarios.

Paso 1 · Reúne ejemplos reales. Empieza con entre 30 y 50 mensajes anonimizados que cubran todas las etiquetas y los casos difíciles.

Paso 2 · Anota la respuesta correcta. Dos personas que anoten la misma muestra revelan dónde las propias etiquetas son ambiguas.

Paso 3 · Mide la versión actual. Ejecuta el script de abajo y guarda el resultado como línea de base.

Paso 4 · Cambia una cosa a la vez. Prompt, modelo o etapa. Vuelve a medir y compara con la línea de base.

Paso 5 · Lee los errores. La lista de errores enseña más que el número: etiqueta ambigua, texto informal, falta de contexto.

Objetivo: medir el clasificador del tema 2 con un conjunto de pruebas (evaluar.py).

# evaluar.py — guárdalo en la misma carpeta que clasificador.py (tema 2)
from collections import Counter
from classificador import classificar

TESTE = [  # (texto, etiqueta correcta) — reemplázalos por más de 30 ejemplos reales y anonimizados
    ("Meu pedido está parado na transportadora há uma semana", "entrega"),
    ("O boleto venceu e não consigo gerar outro", "pagamento"),
    ("A camiseta veio com a costura aberta", "produto"),
    ("Atendimento excelente, resolveram em minutos", "elogio"),
    ("Vocês abrem no feriado?", "outro"),
    ("<texto real>", "<etiqueta correcta>"),
]

tp, fp, fn = Counter(), Counter(), Counter()
erros = []
for texto, certo in TESTE:
    previsto = classificar(texto)["rotulo"]
    if previsto == certo:
        tp[certo] += 1
    else:
        fp[previsto] += 1
        fn[certo] += 1
        erros.append((texto, certo, previsto))

total = len(TESTE)
acertos = sum(tp.values())
print(f"exactitud: {acertos}/{total} = {acertos / total:.0%}")
for r in sorted({c for _, c in TESTE}):
    prec = tp[r] / (tp[r] + fp[r]) if tp[r] + fp[r] else 0.0
    rev = tp[r] / (tp[r] + fn[r]) if tp[r] + fn[r] else 0.0
    print(f"{r:10s} precisión={prec:.2f}  exhaustividad={rev:.2f}")
for texto, certo, previsto in erros:
    print(f"ERROR  esperado={certo:10s} obtenido={previsto:10s} | {texto}")

Cómo verificar: ejecuta python3 avaliar.py (borra antes la línea de ejemplo con < >). Deberías ver la exactitud, una línea por etiqueta y la lista de errores. Cambia el prompt en classificador.py, vuelve a ejecutarlo y compara: si la exactitud subió, pero la de una etiqueta bajó, el cambio no es una victoria completa.

💡 Consejo

Guarda el conjunto de pruebas en el repositorio junto con el código. En el módulo 2.8 se convierte en una barrera automática: ninguna versión pasa a producción si el resultado cae por debajo de la línea de base.

Por qué aprender

Sin un conjunto de pruebas, cada ajuste del prompt es una conjetura y cada cambio de modelo es un riesgo. Con él, puedes cambiar el modelo por uno más barato sabiendo cuánto pierdes, demostrarle la mejora al equipo y encontrar los errores antes de que los vea el cliente.
