🔤 Texto vira dado

NLP (Natural Language Processing, processamento de linguagem natural) é o conjunto de técnicas para um programa ler, organizar e produzir texto humano. O problema de partida é sempre o mesmo: o computador só opera números. Antes de classificar uma reclamação ou resumir um contrato, o texto precisa virar uma sequência de números — e cada escolha feita nessa conversão afeta o resultado lá na frente.

Até por volta de 2018, o trabalho de NLP era dominado por regras e por modelos pequenos treinados para uma tarefa só. Hoje, um LLM faz quase tudo com uma instrução bem escrita. Mas os fundamentos continuam valendo: tokens custam dinheiro e cabem numa janela limitada, texto sujo gera resposta suja e a mesma palavra pode significar coisas diferentes conforme o contexto.

📘 Termos novos

Tokenização é cortar o texto em pedaços (tokens) que estão no vocabulário do modelo. Os modelos atuais usam subpalavras, geradas por algoritmos como BPE (Byte Pair Encoding): palavras comuns viram um token; palavras raras são quebradas em partes. Normalização é padronizar o texto antes de processar — espaços, quebras de linha, caixa, caracteres invisíveis.

O que é

É o caminho texto → tokens → IDs numéricos → vetores. Os vetores (embeddings) carregam o significado que o modelo aprendeu; tudo o que vem depois — classificar, extrair, buscar — opera sobre eles.

✓ Normalize sempre

  • ✓Unicode em forma NFC (acentos compostos e decompostos viram a mesma coisa).
  • ✓Espaços repetidos, tabulações e quebras de linha extras.
  • ✓Assinaturas de e-mail, rodapés e HTML que não carregam significado.
  • ✓Dados pessoais que não precisam ir para o modelo (LGPD, módulo 2.9).

✗ Não destrua o sinal

  • ✗Remover acentos: "pais" e "país" deixam de ser diferentes.
  • ✗Tirar "não" como palavra vazia: a frase inverte de sentido.
  • ✗Converter tudo para minúsculas quando siglas e nomes importam.
  • ✗Apagar emojis em avaliações: eles costumam carregar o sentimento.

💡 Dica

Com LLMs, a limpeza agressiva das técnicas antigas (radicalização, remoção de palavras vazias) atrapalha mais do que ajuda. Limpe ruído de formato e dados pessoais; deixe a linguagem como ela é.

Por que aprender

Entender tokens explica a conta que chega no fim do mês, o motivo de um documento "não caber" no contexto e por que um texto mal limpo confunde o modelo. É a base para dimensionar qualquer pipeline de texto antes de escrever a primeira linha de código.

🏷️ Classificar texto

Classificação de texto é atribuir a cada texto um rótulo de uma lista fechada: o assunto de um chamado, o sentimento de uma avaliação, a urgência de um e-mail, se uma mensagem é spam. É a tarefa de NLP mais comum em empresas, porque permite rotear, contar e priorizar sem ninguém ler tudo.

Existem três caminhos. O clássico transforma o texto em contagens de palavras (TF-IDF) e treina um modelo simples, como regressão logística no scikit-learn — rápido e barato, mas precisa de centenas de exemplos rotulados. O ajuste fino de um modelo pequeno (da família BERT) dá alta qualidade, com custo de treino. E o zero-shot com LLM classifica só com a lista de rótulos e uma instrução, sem treino nenhum.

📘 Termos novos

TF-IDF pesa cada palavra pela frequência no texto e pela raridade no conjunto todo. Zero-shot é fazer a tarefa sem exemplos; few-shot é incluir alguns exemplos no próprio prompt. Saída estruturada é obrigar o modelo a responder num formato legível por máquina, como JSON.

O que é

Uma função que recebe texto e devolve um rótulo de uma lista definida por você, de preferência com uma justificativa curta e num formato que o resto do sistema consegue validar.

Experimente: classificador zero-shot local, salvo como classificador.py.

# Instalação: pip install openai   |   ollama pull qwen2.5:7b
# classificador.py — usa a rota compatível com OpenAI do Ollama (local e grátis)
import json
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")  # o Ollama ignora a chave
ROTULOS = ["entrega", "pagamento", "produto", "elogio", "outro"]

INSTRUCAO = (
    "Você classifica mensagens de clientes de uma loja online. "
    'Responda SOMENTE com JSON no formato {"rotulo": "...", "motivo": "..."}. '
    "Rótulos válidos: " + ", ".join(ROTULOS) + ". "
    "Use 'outro' quando nenhum servir. O motivo tem no máximo 12 palavras."
)

def classificar(texto: str) -> dict:
    resp = client.chat.completions.create(
        model="qwen2.5:7b",
        temperature=0,                              # mesma entrada, mesma saída (quase sempre)
        response_format={"type": "json_object"},    # força JSON válido
        messages=[{"role": "system", "content": INSTRUCAO},
                  {"role": "user", "content": texto}],
    )
    dado = json.loads(resp.choices[0].message.content)
    if dado.get("rotulo") not in ROTULOS:           # nunca confie cegamente na saída
        dado["rotulo"] = "outro"
    return dado

if __name__ == "__main__":
    print(classificar("<cole aqui uma mensagem real de cliente, sem dados pessoais>"))

Como verificar: rode python3 classificador.py. A saída deve ser um dicionário como {'rotulo': 'entrega', 'motivo': '...'}. Teste cinco mensagens de rótulos diferentes e uma que não tem nada a ver com a loja: ela precisa cair em "outro". Para usar uma API paga, troque só base_url, api_key e model.

💡 Dica

Comece pelo LLM para descobrir os rótulos certos e juntar exemplos. Quando o volume crescer e os rótulos estabilizarem, use as respostas revisadas por pessoas para treinar um classificador pequeno e barato. É um caminho comum para reduzir custo sem perder qualidade.

Por que aprender

Quase todo sistema de atendimento, triagem ou análise de opinião começa com uma classificação. Saber escolher entre o caminho clássico, o ajuste fino e o LLM — e validar a saída — evita tanto o projeto caro demais quanto o que quebra na primeira resposta fora do formato.

🧾 Extrair entidades

NER (Named Entity Recognition, reconhecimento de entidades nomeadas) é encontrar no texto os nomes de pessoas, empresas, lugares, datas e valores, e dizer o tipo de cada um. Com isso, um contrato vira uma linha de planilha: partes, valor, prazo, foro. Uma notícia vira uma lista de empresas citadas.

Há duas famílias de ferramentas. Bibliotecas como o spaCy trazem modelos prontos para português (pt_core_news_sm) que marcam pessoa, local e organização com rapidez e custo zero. Para campos do seu negócio (número do pedido, nome do produto, cláusula de multa), um LLM com esquema JSON costuma ser mais flexível: você descreve os campos e o modelo preenche.

📘 Termos novos

JSON Schema é uma descrição formal dos campos, tipos e obrigatoriedades de um JSON. O Ollama aceita esse esquema no parâmetro format e restringe a geração para que a resposta caiba nele. Etiquetas BIO (Begin, Inside, Outside) são o jeito clássico de marcar entidades palavra por palavra no treino de modelos de NER.

O que é

Extração de informação: localizar trechos com significado específico dentro do texto livre e devolvê-los organizados por tipo, prontos para ir a um banco de dados ou a outra etapa do pipeline.

Objetivo: extrair entidades com esquema JSON e checar se nada foi inventado.

# Instalação: pip install requests   |   ollama pull qwen2.5:7b
import json, requests

CAMPOS = ["pessoas", "organizacoes", "locais", "datas", "valores"]
SCHEMA = {
    "type": "object",
    "properties": {c: {"type": "array", "items": {"type": "string"}} for c in CAMPOS},
    "required": CAMPOS,
}

def extrair(texto: str) -> dict:
    r = requests.post("http://localhost:11434/api/chat", json={
        "model": "qwen2.5:7b",
        "stream": False,
        "format": SCHEMA,                 # a resposta é restrita a este esquema
        "options": {"temperature": 0},
        "messages": [
            {"role": "system", "content": "Extraia as entidades do texto. Copie cada trecho "
             "exatamente como aparece. Não invente: use lista vazia quando não houver."},
            {"role": "user", "content": texto},
        ],
    }, timeout=120)
    r.raise_for_status()
    return json.loads(r.json()["message"]["content"])

texto = "<cole um parágrafo de contrato, notícia ou e-mail>"
ents = extrair(texto)
print(json.dumps(ents, ensure_ascii=False, indent=2))

# Checagem anti-invenção: todo trecho precisa existir literalmente no texto
for tipo, itens in ents.items():
    for item in itens:
        if item not in texto:
            print(f"ATENÇÃO [{tipo}] não está no texto: {item!r}")

Como verificar: com a frase do diagrama, a saída deve ter as cinco listas preenchidas e nenhuma linha "ATENÇÃO". Depois cole um texto sem datas: datas deve voltar vazia. Se aparecer um aviso, o modelo reescreveu ou inventou um trecho — trate como erro, não como acerto.

💡 Dica

Para entidades padrão em grande volume, teste o spaCy antes: pip install spacy e python -m spacy download pt_core_news_sm. Ele roda em CPU, sem GPU, e serve de base de comparação para o LLM.

Por que aprender

Boa parte do valor de NLP em empresas está em tirar dados de documentos: notas, contratos, laudos, currículos, e-mails. Saber extrair com esquema e verificar contra o texto original é o que separa uma demonstração de um processo em que se pode confiar.

📄 Resumir textos longos

Resumir parece simples até o documento passar de algumas dezenas de páginas. Mesmo com janelas de contexto grandes, modelos tendem a dar menos atenção ao miolo de textos muito longos, e um resumo único esconde de onde veio cada afirmação. O método robusto é dividir, resumir as partes e depois juntar, guardando a referência de cada trecho.

Há dois tipos de resumo. O extrativo escolhe frases do original e as copia — seguro, porque nada é reescrito. O abstrativo reescreve com outras palavras — mais fluido, mas pode distorcer. Em textos jurídicos, médicos ou financeiros, um meio-termo funciona bem: resumo abstrativo com citação literal dos trechos que sustentam cada ponto.

📘 Termos novos

Chunking é dividir o documento em trechos (chunks) de tamanho controlado, de preferência respeitando seções e parágrafos. Sobreposição (overlap) é repetir um pedaço do fim de um trecho no começo do próximo para não cortar uma ideia ao meio. Map-reduce é aplicar a mesma operação em cada trecho (map) e depois combinar os resultados (reduce).

O que é

Resumo em etapas: o documento é dividido em trechos, cada trecho recebe um resumo parcial com referência à origem e, no fim, um resumo final combina os parciais seguindo o formato que o leitor precisa.

Para quem decide

Cinco pontos, riscos primeiro, cada um com a página de origem. Termine com "o que falta decidir".

Para quem executa

Lista de obrigações, prazos e responsáveis em tabela. Nada de parágrafos longos.

Para o sistema

JSON com campos fixos (tema, partes, datas, valores) para indexar e filtrar depois.

💡 Dica

Divida por estrutura (títulos, cláusulas, seções), não por número fixo de caracteres. Um corte no meio de uma cláusula gera dois resumos parciais errados.

Por que aprender

Relatórios, atas, processos e manuais são longos e lidos com pressa. Um resumo rastreável economiza horas de leitura sem esconder de onde veio cada conclusão — e o mesmo padrão de dividir, processar e juntar serve para tradução, extração e revisão de documentos grandes.

🔎 Busca semântica

A busca por palavra-chave só acha o que tem a mesma palavra. Quem pergunta "minha encomenda não chegou" não encontra o texto "prazo de entrega" — embora seja exatamente o que procura. A busca semântica compara significados: transforma pergunta e documentos em vetores e devolve os documentos cujos vetores estão mais próximos.

Essa é a peça central do RAG (geração aumentada por recuperação), visto no módulo sobre bases de conhecimento: antes de responder, o sistema busca os trechos relevantes e os entrega ao LLM. Em produção, os vetores ficam num banco próprio — pgvector no Postgres, Qdrant ou Chroma. Para aprender, um array do NumPy basta.

📘 Termos novos

Similaridade de cosseno mede o ângulo entre dois vetores: perto de 1, apontam para o mesmo lado (significados parecidos); perto de 0, não têm relação. Se os vetores forem normalizados (comprimento 1), o cosseno vira um simples produto escalar. Busca híbrida combina palavra-chave e vetor, útil quando códigos e nomes exatos importam.

O que é

Busca por proximidade de significado: um modelo de embeddings converte textos em vetores, e a consulta devolve os textos mais próximos da pergunta pelo cosseno, mesmo sem palavras em comum.

Experimente: busca semântica local com nomic-embed-text.

# Instalação: pip install requests numpy   |   ollama pull nomic-embed-text
import requests
import numpy as np

def embed(textos: list[str]) -> np.ndarray:
    r = requests.post("http://localhost:11434/api/embed",
                      json={"model": "nomic-embed-text", "input": textos}, timeout=120)
    r.raise_for_status()
    v = np.array(r.json()["embeddings"], dtype=float)
    return v / np.linalg.norm(v, axis=1, keepdims=True)   # normaliza: cosseno = produto escalar

# O nomic-embed-text recomenda prefixos diferentes para documento e consulta
docs = [
    "O prazo de entrega é de 5 a 10 dias úteis após a confirmação do pagamento.",
    "Boletos vencidos podem ser reemitidos na área do cliente.",
    "Trocas são aceitas em até 7 dias corridos após o recebimento.",
    "<acrescente aqui trechos da sua própria base, um por item>",
]
D = embed(["search_document: " + d for d in docs])

def buscar(pergunta: str, k: int = 2) -> None:
    q = embed(["search_query: " + pergunta])[0]
    notas = D @ q
    for i in np.argsort(-notas)[:k]:
        print(f"{notas[i]:.3f}  {docs[i]}")

buscar("minha encomenda ainda não chegou")

Como verificar: o primeiro resultado deve ser a frase do prazo de entrega, mesmo sem a palavra "encomenda" nela. Troque a pergunta por "posso devolver a camiseta?" — a frase de trocas deve subir para o topo. As notas mudam de modelo para modelo; compare a ordem, não o valor absoluto.

Por que aprender

Busca semântica é a base de assistentes que respondem com documentos da empresa, de deduplicação de chamados e de recomendação de conteúdo. Entender o vetor e a métrica permite diagnosticar por que uma busca falha — antes de culpar o LLM pela resposta ruim.

🌍 Português e outros idiomas

A maior parte dos dados de treino dos modelos ainda é em inglês. Os LLMs atuais lidam bem com português, mas aparecem diferenças: mais tokens para o mesmo conteúdo, gírias e regionalismos mal interpretados, confusão entre português do Brasil e de Portugal e erros em formatos locais — CPF, CEP, datas no formato dia/mês, vírgula decimal, "R$ 1.234,56".

Para tradução, você tem modelos dedicados abertos, como o NLLB da Meta, e os LLMs gerais, que traduzem bem e ainda seguem instruções de tom e glossário. Para sistemas que recebem textos em várias línguas, o padrão é detectar o idioma primeiro e decidir: processar no idioma original com um modelo multilíngue ou traduzir antes.

📘 Termos novos

Modelo multilíngue é treinado em vários idiomas ao mesmo tempo e coloca frases equivalentes perto no espaço de embeddings — por isso uma pergunta em português pode achar um documento em espanhol. Glossário, em tradução, é a lista de termos que devem ser traduzidos sempre do mesmo jeito (ou não traduzidos, como nomes de produto).

O que é

É tratar idioma e formato local como parte do problema: detectar a língua, escolher modelo e prompt adequados, padronizar números, datas e documentos brasileiros e testar com textos reais do seu público.

✓ Funciona bem

  • ✓Pedir explicitamente "português do Brasil" no prompt de sistema.
  • ✓Converter "R$ 1.234,56" e "03/02/2026" com código, não com o modelo.
  • ✓Validar CPF e CNPJ pelo dígito verificador depois da extração.
  • ✓Glossário fixo no prompt de tradução para termos da empresa.

✗ Armadilhas comuns

  • ✗Testar só com textos em inglês e publicar para clientes brasileiros.
  • ✗Deixar o modelo interpretar "02/03" sem saber o formato de data.
  • ✗Ignorar textos com erros de digitação e abreviações de WhatsApp.
  • ✗Traduzir e depois extrair, perdendo nomes e valores originais.

💡 Dica

Monte seu conjunto de testes com mensagens como o seu cliente escreve de verdade — com "vc", "pq", erros e áudio transcrito. Modelos que vão bem em texto limpo podem cair bastante em texto informal, e só o teste mostra quanto.

Por que aprender

Exemplos, tutoriais e benchmarks costumam ser em inglês. Quem constrói para o público brasileiro precisa conhecer as falhas típicas em português e os formatos locais — é aí que um sistema que "funcionou no teste" quebra com o primeiro cliente real.

🧪 Pipeline e avaliação

Um pipeline de texto encadeia as etapas deste módulo: normalizar, detectar idioma, classificar, extrair, validar e gravar. Cada etapa tem entrada e saída definidas, e cada uma pode falhar. Sem medir, você não sabe qual etapa errou nem se uma troca de modelo ou de prompt melhorou ou piorou o resultado.

A ferramenta para isso é o conjunto de testes: algumas dezenas de exemplos reais, anonimizados, com a resposta certa anotada por uma pessoa. Toda mudança roda contra ele. O número que sai não precisa ser perfeito; precisa ser comparável entre versões.

📘 Termos novos

Acurácia é a fração de acertos no total. Precisão de um rótulo: dos itens que o modelo marcou com ele, quantos estavam certos. Revocação (recall): dos itens que realmente eram daquele rótulo, quantos o modelo encontrou. F1 combina as duas. Em classes desbalanceadas, olhe precisão e revocação por rótulo, não só a acurácia.

O que é

Uma sequência de etapas de texto com contrato de entrada e saída, acompanhada de um conjunto de testes rotulado que mede cada mudança antes de ela chegar aos usuários.

Passo 1 · Junte exemplos reais. Comece com 30 a 50 mensagens, anonimizadas, cobrindo todos os rótulos e os casos difíceis.

Passo 2 · Anote a resposta certa. Duas pessoas anotando a mesma amostra revelam onde os próprios rótulos são ambíguos.

Passo 3 · Meça a versão atual. Rode o script abaixo e guarde o resultado como linha de base.

Passo 4 · Mude uma coisa por vez. Prompt, modelo ou etapa. Meça de novo e compare com a linha de base.

Passo 5 · Leia os erros. A lista de erros ensina mais que o número: rótulo ambíguo, texto informal, falta de contexto.

Objetivo: medir o classificador do tópico 2 com um conjunto de testes (avaliar.py).

# avaliar.py — salve na mesma pasta do classificador.py (tópico 2)
from collections import Counter
from classificador import classificar

TESTE = [  # (texto, rótulo certo) — troque por 30+ exemplos reais e anonimizados
    ("Meu pedido está parado na transportadora há uma semana", "entrega"),
    ("O boleto venceu e não consigo gerar outro", "pagamento"),
    ("A camiseta veio com a costura aberta", "produto"),
    ("Atendimento excelente, resolveram em minutos", "elogio"),
    ("Vocês abrem no feriado?", "outro"),
    ("<texto real>", "<rótulo certo>"),
]

tp, fp, fn = Counter(), Counter(), Counter()
erros = []
for texto, certo in TESTE:
    previsto = classificar(texto)["rotulo"]
    if previsto == certo:
        tp[certo] += 1
    else:
        fp[previsto] += 1
        fn[certo] += 1
        erros.append((texto, certo, previsto))

total = len(TESTE)
acertos = sum(tp.values())
print(f"acurácia: {acertos}/{total} = {acertos / total:.0%}")
for r in sorted({c for _, c in TESTE}):
    prec = tp[r] / (tp[r] + fp[r]) if tp[r] + fp[r] else 0.0
    rev = tp[r] / (tp[r] + fn[r]) if tp[r] + fn[r] else 0.0
    print(f"{r:10s} precisão={prec:.2f}  revocação={rev:.2f}")
for texto, certo, previsto in erros:
    print(f"ERRO  esperado={certo:10s} veio={previsto:10s} | {texto}")

Como verificar: rode python3 avaliar.py (apague antes a linha de exemplo com < >). Você deve ver a acurácia, uma linha por rótulo e a lista de erros. Mude o prompt em classificador.py, rode de novo e compare: se a acurácia subiu mas um rótulo caiu, a mudança não é uma vitória completa.

💡 Dica

Guarde o conjunto de testes no repositório, junto do código. No módulo 2.8 ele vira um portão automático: nenhuma versão vai para produção se o resultado cair abaixo da linha de base.

Por que aprender

Sem conjunto de testes, cada ajuste de prompt é um palpite e cada troca de modelo é um risco. Com ele, você troca o modelo por um mais barato sabendo quanto perde, prova a melhoria para o time e encontra os erros antes do cliente.
